`www` remains draft-001.

## Hosting

- Existing Nginx Proxy Manager container `npm` owns ports 80/443.
- Proxy host **9** routes `koreokorp.com` to `koreokorp-web:80` on Docker network `edge`.
- Let's Encrypt certificate **10** expires on 2027-01-02 and is managed by
  Proxy Manager's automatic renewal. HTTP redirects to HTTPS.
- Container `koreokorp-web` serves `/var/www/koreokorp/current` with Nginx.
  It has a read-only filesystem, a health check, and `unless-stopped` restart policy.
  Docker is enabled at boot. No host port is published for this container.
- Releases live under `/var/www/koreokorp/releases/`; `current` is an atomic symlink.
  Only the self-contained `index.html` and a commit marker are published.

## VPS files

- `/opt/stacks/koreokorp/compose.yaml`: container definition and pinned image.
- `/opt/stacks/koreokorp/nginx.conf`: static serving, cache policy, gzip, and headers.
- `/opt/stacks/koreokorp/deploy.sh`: creates a release from the checkout's committed HEAD.
- `/opt/stacks/koreokorp/backups/`: root-only Proxy Manager database backup before setup.
- `/var/www/koreokorp/current`: active release.
- `/opt/stacks/npm/data/nginx/proxy_host/9.conf`: generated by Proxy Manager.
- `/opt/stacks/npm/data/database.sqlite`: Proxy Manager host and certificate records.
- `/opt/stacks/npm/letsencrypt/`: managed certificate files and renewal configuration.

Manage the domain route and certificate through Proxy Manager; do not hand-edit its
generated host configuration. Other existing sites retain their configuration.

## Update

Commit the desired prototype changes first. Run validation as the checkout owner:

```bash
cd /home/korebear/Kkorp
npm ci
npm test
git diff --check
sudo /opt/stacks/koreokorp/deploy.sh /home/korebear/Kkorp
curl --fail --silent --show-error --head https://koreokorp.com
```

The deployment script publishes committed HEAD, keeps previous releases, and
records the previous symlink target in `/opt/stacks/koreokorp/previous-release`.
Content updates take effect without restarting either web server.

For container/configuration changes:

```bash
sudo docker compose -f /opt/stacks/koreokorp/compose.yaml config --quiet
sudo docker compose -f /opt/stacks/koreokorp/compose.yaml run --rm --no-deps web nginx -t
sudo docker compose -f /opt/stacks/koreokorp/compose.yaml up -d
sudo docker exec koreokorp-web nginx -t
sudo docker exec koreokorp-web nginx -s reload
```

## Roll back

After a subsequent deployment, restore the recorded previous release:

```bash
sudo bash <<'SH'
set -euo pipefail
previous=$(cat /opt/stacks/koreokorp/previous-release)
[[ "$previous" == releases/* ]]
test -f "/var/www/koreokorp/$previous/index.html"
ln -s "$previous" /var/www/koreokorp/current.rollback
mv -Tf /var/www/koreokorp/current.rollback /var/www/koreokorp/current
SH
curl --fail --silent --show-error --head https://koreokorp.com
```

The first deployment has no earlier release to restore.

`previous-release` is written by `deploy.sh` as root with mode 640, so read it
through `sudo` as the block above does.

# The application on staging

The Next.js application is deployed and verified at
**https://staging.koreokorp.com**. It is **not** serving koreokorp.com: proxy
host 9 still points at the `koreokorp-web` static container, and repointing it is
TASK-018, a separate deliberate step.

The application's visual state is incomplete. The canvas engines are not ported
yet, so the landing shows an empty ellipse where the jelly logo belongs.

## Application files on the VPS

| Path | What |
|---|---|
| `/opt/stacks/koreokorp/compose-app.yaml` | The `app` service. Separate from `compose.yaml` so the live static site cannot be disturbed. |
| `/opt/stacks/koreokorp/deploy-app.sh` | Builds a commit-tagged image, starts it, waits for health, records the rollback target. |
| `/opt/stacks/koreokorp/previous-release-app` | The rollback target: a commit SHA, mode 644, no secret. |
| `/opt/stacks/koreokorp/app.env` | Not created yet. The site runs with no environment variables until TASK-017 needs any. |

`deploy.sh` is **deliberately unmodified**. It publishes the static prototype and
is the production rollback target; `deploy-app.sh` is its companion.

## Proxy Manager objects

| Id | Domain | Forwards to | Certificate |
|---|---|---|---|
| 9 | `koreokorp.com` | `koreokorp-web:80` | 10, expires 2027-01-02 |
| 10 | `staging.koreokorp.com` | `koreokorp-app:3000` | 11, expires 2027-01-02 |

Both were created through the Proxy Manager API. Note for future automation: the
API rejects the extra fields its own UI sends (`agree`, `ssl_forcesh`), requires
`forward_scheme`, and its update route is the **plural** `/nginx/proxy-hosts/:id`.
Response headers must use `more_set_headers`, not `proxy_set_header`, because
Proxy Manager emits its own `proxy_set_header` directives inside the location
block and they override server-level ones.

To remove staging: delete proxy host 10 and certificate 11 in Proxy Manager, then
`sudo docker compose -f /opt/stacks/koreokorp/compose-app.yaml down`. The DNS
record may stay; an unconfigured name simply does not resolve in Proxy Manager.

## Update

```bash
cd /home/korebear/Kkorp
npm run lint && npm run typecheck && npm test && npm run test:app
git diff --check
sudo /opt/stacks/koreokorp/deploy-app.sh /home/korebear/Kkorp
KOREOKORP_STAGING=1 npm run test:app -- tests/app/staging-tls.spec.js
```

The script refuses to deploy uncommitted application changes, because the image
tag is derived from the commit and would otherwise be a lie.

`npm run test:app` needs a current build, because it boots
`.next/standalone/server.js`; run `npm run build` first. It selects
`playwright.app.config.js` explicitly. It must: the root `playwright.config.js`
sets `testIgnore: '**/app/**'`, so a bare `playwright test tests/app` matches no
tests and exits 1.

## Roll back the application

```bash
previous=$(cat /opt/stacks/koreokorp/previous-release-app)
sudo docker tag "koreokorp-app:$previous" koreokorp-app:current
sudo env KOREOKORP_RELEASE="$previous" \
  docker compose -f /opt/stacks/koreokorp/compose-app.yaml up -d
curl --fail --silent --show-error --head https://staging.koreokorp.com
```

This was rehearsed, not just written: rolled forward from `a41a4a45ea4e` to
`ac8fe5b2e6b6`, back to `a41a4a45ea4e`, then forward again, verifying health and
the TLS suite at each step. Rolling back to the **static prototype** instead uses
the unchanged `previous-release` symlink procedure above.

Migrations are not rolled back automatically, so every migration must stay
backward compatible with the previous release. TASK-017 owns that rule.
